## 1. **"Unsupported agent type: multiagent"**  
```
FAILED tests/test_agent_factory.py::test_create_multi_agent
ValueError: Unsupported agent type: multiagent
FAILED tests/test_agent_factory.py::test_multi_agent_configuration
ValueError: Unsupported agent type: multiagent
```

### 원인  
- 코드상 `agent_factory.py`에서 `elif agent_type == "multiagent": ... MultiAgentManager(...)` 분기를 만들었는데,  
- 테스트는 `"MultiAgent"`(대문자)로 호출하거나, 혹은 `"multi_agent"` 등 다른 문자열을 쓰고 있을 수 있음.  
- 혹은 실제 분기에서 `'multiagent'`가 아닌 `'MultiAgent'`를 검사하고 있거나.  

**또는**  
- 만약 `"MultiAgentManager"`를 만들기 위해 `agent_type="multiagent"`를 주면 코드상에는 `'multiagent'`를 `ValueError(f"Unsupported agent type: ...")`로 처리하도록 되어 있는 부분이 남아 있을 수도 있습니다.  

### 해결  
1. 테스트에서 `"MultiAgent"` 대신 `"multiagent"`로 통일 (혹은 반대로).  
2. `agent_factory.py`에서 `elif agent_type in ["multiagent", "multi_agent", "MultiAgent"]:` 식으로 처리.  
3. 실제 내부에서 `raise ValueError(f"Unsupported agent type: ...")`가 아니라 `MultiAgentManager(agent_configs=...)`를 호출하도록 로직 보정.  

즉, **테스트와 코드가 같은 문자열**을 쓰도록 맞춰주면 됩니다.

## 2. **`test_agent_behavior_differentiation`: Momentum vs MeanReversion 액션 비교 실패**  
```
AssertionError: Expected Momentum agent to be more bullish than MeanReversion in uptrend.
Got Momentum: [0.2062...], MeanReversion: [1.0]
```

### 원인  
- 테스트는 “상승 추세가 뚜렷한 obs에서 MomentumAgent의 액션 > MeanReversionAgent의 액션”을 기대.  
- 그런데 실제 계산 로직이 반대로 나오거나, MeanReversion이 더 큰 액션(1.0)을 내고, Momentum은 0.2 정도만 내는 상황.  

### 해결  
- **MeanReversionPPOAgent**와 **MomentumPPOAgent**가 obs를 어떻게 분석해서 action을 도출하는지(추가 feature 계산, 보정 로직 등)를 다르게 해야 함.  
- 지금 상태로는 “둘 다 PPO 기반 + 약간 다른 feature”지만, PPO 초기화값이나 feature 해석 로직 때문에 MeanReversion이 더 강한 매수로 나오고 있는 것.  
- 이 테스트가 “하드하게 Momentum>MeanRev”를 요구한다면, **전략 로직**(예: “MeanReversion이면 상승장에는 보수적으로, Momentum이면 적극적으로”)을 명시적으로 만들어야 합니다.  
- 만약 RL이라면, 초기 파라미터 단계에서는 누가 더 “bullish”일지 보장 안 됨 → 그럼 이 테스트 자체가 “학습 전 초기화 동작”에 대한 가정을 과하게 하는 것일 수도 있음.

**간단히**  
- MeanReversion agent가 상승 시 -1.0~+1.0 범위에서 약하게 동작하도록 하거나, Momentum이 더 크게 동작하도록 임시 로직을 넣는 식.  
- 혹은 테스트를 완화해서 “Momentum != MeanReversion” 정도로만 체크.

## 3. **shape mismatch**: “The size of tensor a (5) must match the size of tensor b (50) …”  
```
FAILED tests/test_agent_factory.py::test_agent_state_initialization - RuntimeError: The size of tensor a (5) must match the size of tensor b (100) ...
FAILED tests/test_components.py::TestNetworks::test_policy_network_shapes - TypeError: cannot unpack non-iterable Normal object
FAILED tests/test_components.py::TestPPOAgent::test_get_action_shape - RuntimeError: The size of tensor a (5) must match the size of tensor b (50) ...
FAILED tests/test_integration.py::test_training_to_hyperopt_flow - RuntimeError: The size of tensor a (5) must match the size of tensor b (50) ...
...
```

### 원인 (대표 예시)  
- **PolicyNetwork**가 “(window_size * features)” 차원 인풋을 기대(예: 20*5=100).  
- 테스트는 “(5,)”짜리 state(혹은 (4,3)=12차원) 등을 넣고 `network.forward(...)` 호출.  
- 당연히 MLP에서 “Linear(in=100, out=256)” 레이어가 있는데 실제 input은 5 dimension → mismatch.

**또한**  
- `"TypeError: cannot unpack non-iterable Normal object"` → 예전 테스트가 “`mean, std = network(x)`”라고 했는데, 지금 코드는 “`return Normal(mean, std)`”만 하고 있을 수도 있음.

### 해결  
1. 테스트에서 state shape를 네트워크가 기대하는 `(window_size, features)` or `(batch_size, window_size, features)` 형태로 만들어야 함.  
2. 만약 네트워크가 “(1, 100)“을 기대하면, 테스트는 “torch.randn(1,100)” 식으로 만들어야 함.  
3. 혹은 **코드를** 예전처럼 `(mean, std)` 튜플을 리턴하도록 바꾼 뒤, `Normal(mean, std)`는 PPOAgent가 따로 만드는 방식.  

**즉**, “테스트와 실제 Network 로직”이 맞도록 정렬해야 합니다.

Both your Momentum and MeanReversion PPO agents are presumably untrained, using random initialization (or the same default init), so they might produce similar or identical policy outputs.

1. **Relax the test** to check they produce *different* actions, not necessarily *strictly greater*. For instance:

   assert momentum_action[0] != mean_rev_action[0], \
