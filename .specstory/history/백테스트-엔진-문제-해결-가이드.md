아래 내용들은 이미 올려주신 파일(backtest_engine.py, backtest_manager.py, experimental_backtester.py, test_experimental_backtester.py, test_backtest_execution.py, test_agent_interaction.py)들을 전반적으로 살펴본 뒤, “부분 청산 문제”, “평단(entry price) 계산 문제”, “포지션 크기 제한(10% vs 10.9% 초과)”, 그리고 “테스트에서 기대하는 값과 실제 계산값의 불일치”가 왜 생기는지 함께 살펴보는 가이드입니다.

1. 부분 청산 vs 숏 진입(혹은 신규 포지션)

문제 징후
	•	experimental_backtester.py의 execute_trade()를 보면, action < 0일 때 모두 “매도(또는 숏 진입)”로 처리되는데, 실제로는 “기존 롱 포지션을 청산”이냐 “새로 숏(음수) 포지션을 잡는”이냐 구분이 애매합니다.
	•	테스트에서는 “매도 액션이 들어오면, 기존 포지션의 일부 혹은 전부를 청산”이라고 가정하지만, 코드 상에는 “숏 포지션(음수) 진입”이 같은 분기(action < 0)에 섞여 있기도 합니다.
	•	test_partial_position_closure 등에서 “action = -0.25”를 주면 “현재 포지션의 50% 청산”을 기대하지만, 코드에서는 “(current_position * 2 * abs(action))” 같은 수식 때문에 오차가 벌어집니다.

해결 아이디어 (간단 버전)
	•	롱/숏 분리: “￼”가 들어오면, 먼저 “￼”인지 확인해 “롱 포지션 청산”으로 처리. 만약 old_pos == 0(혹은 음수)라면 “숏 진입” 로직으로 처리.
	•	부분 청산 공식:
\[
\text{close\_size} = \text{old\_pos} \times \lvert \text{action} \rvert
\quad \text{(ex. action = -0.25 → 포지션의 25% 청산)}
\]
이 정도면 “현재 포지션의 25% 청산”이 됩니다.
	•	완전 청산 (ex. action <= -1.0): trade_size = -old_pos 로 전부 청산.

이러한 분기만 명확히 해도, “부분 청산 vs 전부 청산 vs 숏 진입”이 보다 정확히 반영될 것입니다.

2. 평단(entry price) 추적

문제 징후
	•	테스트에서는 “여러 번 매수할 경우, 가중 평균으로 entry price가 업데이트”를 기대합니다.
	•	test_position_entry_price_tracking 에서

total_size = result1["size"] + result2["size"]
expected_entry_price = (result1["size"] * price1 + result2["size"] * price2) / total_size

형태로 검증.

	•	실제 코드를 보면, 첫 매수 시에는 그냥 current_price로 세팅, 추가 매수 시에는 (old_value + new_value) / total_size로 가중평균.
	•	그런데 “result1[“size”] vs trade_size”가 달라질 수 있는 부분이 있음.

해결 아이디어
	•	‘trade_result[“size”]’와 실제 포지션 증감분이 동일해야 함.**
	•	즉, “이 트레이드로 +2.0 물량을 샀다”면 trade_result["size"] == 2.0이 되어야, 테스트에서 result1["size"] + result2["size"]를 정확히 쓸 수 있음.
	•	‘가중평균 공식을 한 군데에서만’(코어 로직) 책임지고 계산하도록.
	•	첫 매수 시도(현재 포지션=0) → entry_prices[asset] = current_price.
	•	이후 매수(현재 포지션>0) → new_entry_price = ( old_pos * old_entry_price + trade_size * current_price ) / (old_pos + trade_size ).
	•	부분 청산 시(현재 포지션>0, action < 0) → 실제 청산 분만큼 pnl이 실현되고, 남은 포지션 수량은 그대로 entry_price 유지(혹은 새로 계산).
	•	전부 청산 시 → entry_prices[asset] 삭제.

3. 포지션 크기 제한 (10% vs 10.93% 등)

문제 징후
	•	test_risk_management_integration에서 max_position_size = 10 (즉 10%)인데, 테스트 결과 10.9336% > 10%라고 오류 뜸.
	•	보통은 부동소수점 오차 0.1~0.2% 정도 허용하면 해결되기도 하나, 10.93%는 꽤 크게 넘은 상태.

해결 아이디어
	•	주문 직전에 다시 한 번 check:

trade_value = abs(trade_size * current_price)
max_position_value = portfolio_value * self.risk_config.max_position_size
if trade_value > max_position_value * 1.001:
    scale = (max_position_value / trade_value) * 0.99
    trade_size *= scale

처럼 잘라버리면 결코 10% 넘지 않습니다.

	•	테스트 허용 오차: 테스트에서 position_size_pct <= 10 * 1.001 정도.
	•	이중 적용: 만약 “VaR limit”이라든지 “잔고 수수료 로직”으로 포트폴리오 가치가 순간적으로 변동되어서 10.93%가 되는 경우가 있을 수 있으므로, trade 체결 직후 포트폴리오 가치가 바뀌었을 가능성을 고려. → 보수적으로 줄이거나, 테스트에서 1~2% 정도 허용.

4. 로그 상 중복 기록, PnL 누락 등

6. 올려주신 코드 중 “수정하면 좋은 부분”
	1.	experimental_backtester.py → execute_trade
	•	현재 “action < 0”일 때 close_size = current_position * (2 * abs(action)) 같은 계산이 테스트 기대와 달라 문제. → 부분 청산은 “current_position * abs(action)”가 기대치. (예: -0.25면 25% 청산이지 50% 청산이 아님)
	•	만약 테스트에서 “-0.25” = “절반 청산”을 원한다면, 현재 로직은 “(2*abs(action))=0.5”로 계산하고 있어서 충돌이 생길 수 있음(반대로 해석).
	•	(A) 테스트 의도에 맞추려면, "action=-0.25" → 포지션 25% 청산; (B) 기존 코드 의도에 맞추려면, 테스트를 수정해야 함.
	2.	entry_price 갱신
	•	매수 시 entry_prices[asset] = (old_value + new_value) / (old_pos + trade_size)
	•	주의: old_value는 (old_pos * old_entry_price), new_value = (trade_size * current_price).
	•	실제로 trade_result["size"](체결된 실제 증감분)와 trade_size가 같아야, 테스트에서 result["size"]를 그대로 쓰는데 문제 없습니다.
	3.	중복 기록
	•	만약 상위 BacktestManager에서도 trade를 추가한다면, execute_trade 내부의 self.trades.append(trade_result)를 빼야 함.

결론

현재 문제(“부분 청산 테스트 실패”, “평단 불일치”, “포지션 크기 10.93% 초과”, “테스트와 실제 값 오차 0.7~0.8”)는 크게 세 갈래입니다:
	1.	부분 청산/액션 해석 로직이 테스트 기대와 코드가 달라 충돌(예: -0.25를 25% vs 50%로 해석).
	2.	평단 계산 시 “result1[“size”]”와 “trade_size”가 어긋나거나, 첫 매수 시에도 가중평균 적용/미적용이 달라서 mismatch.
	3.	포지션 제한이 float 연산으로 10% 살짝 넘음 → 엄격하게 잘라주거나 테스트 허용오차 늘림.

개선 방향 요약:
	•	(A) “부분 청산은 action=-x → 현재 포지션의 x만큼 청산”을 코드상 명시.
	•	(B) 첫 매수 시 entry_price = current_price, 이후 매수 시 (old_pos * old_entry_price + trade_size * current_price)/ (old_pos + trade_size).
	•	(C) 포지션 크기 → ‘체결 직전’에 강제 clamp(절대 10% 넘지 못하게). + 테스트 허용오차 1~2%.

이 정도만 맞춰도, 현재 테스트(test_partial_position_closure, test_position_entry_price_tracking, test_complete_position_closure, test_risk_management_integration, etc.)의 대부분 실패가 해결될 것입니다.


결국 “어떤 부분을 뜯어 고치면 좋은가?”에 대한 짧은 답변은,
	1.	execute_trade() 로직에서 부분 청산/완전 청산/새 매수(평단 업데이트) 분기를 테스트 기대에 맞게 정확히 분리.
	2.	포지션 사이즈는 “매수액 vs 포트폴리오 가치”로 환산 후 10% 넘지 않도록 clamp.
	3.	평단(Entry Price) 계산은 “체결된 trade_size”와 “이전 pos * 이전 평단”을 정확히 써서 가중 평균을 구하도록.
	4.	테스트에서 result1["size"]가 실제 체결분과 같도록, 그리고 이 값으로 평단/부분 청산 계산.

```
class ExperimentalBacktester(BacktestEngine):
    """Experimental backtester with improved position management and PnL calculation."""
    
    def __init__(self, data: pd.DataFrame, risk_config: RiskConfig, initial_balance: float = 10000.0):
        super().__init__(
            initial_capital=initial_balance,
            transaction_cost=0.001,  # Default trading fee
            max_position=risk_config.max_position_size
        )
        self.data = data
        self.risk_config = risk_config
        self.entry_prices: Dict[str, float] = {}  # Track entry prices per asset
        self.positions: Dict[str, float] = {}     # Track positions per asset
        self.trading_fee = 0.001  # For compatibility with tests
    
    def _calculate_trade_revenue(self, asset: str, trade_size: float, current_price: float) -> Dict[str, float]:
        """Calculate trade revenue and PnL for position closure."""
        old_pos = self.positions.get(asset, 0)
        entry_price = self.entry_prices.get(asset, current_price)
        
        if trade_size < 0 and old_pos > 0:  # Closing long position
            # Calculate actual closure size
            close_size = min(abs(trade_size), old_pos)
            
            # Calculate gross revenue and fees
            gross_revenue = close_size * current_price
            fee = gross_revenue * self.trading_fee
            net_revenue = gross_revenue - fee
            
            # Calculate realized PnL
            realized_pnl = close_size * (current_price - entry_price) - fee
            
            return {
                "revenue": net_revenue,
                "pnl": realized_pnl,
                "close_size": close_size
            }
        
        # For new positions or position increases
        trade_value = abs(trade_size) * current_price
        fee = trade_value * self.trading_fee
        
        if trade_size > 0:  # Opening/increasing long position
            return {
                "cost": trade_value + fee,
                "pnl": -fee,
                "close_size": 0
            }
        else:  # Opening short position (if allowed)
            return {
                "revenue": trade_value - fee,
                "pnl": -fee,
                "close_size": 0
            }
    
    def execute_trade(self, timestamp: pd.Timestamp, action: float, price_data: Dict[str, float]) -> Dict[str, Any]:
        """Execute trade with improved position management and PnL calculation."""
        if abs(action) < self.risk_config.min_trade_size:
            return {
                "timestamp": timestamp,
                "action": "skip",
                "reason": "action too small",
                "position": sum(self.positions.values())
            }
        
        current_price = price_data.get("$close", price_data.get("close"))
        if not current_price:
            raise ValueError("Price data must contain 'close' or '$close'")
        
        # Calculate portfolio value and maximum allowed position
        portfolio_value = self.get_portfolio_value({"default": current_price})
        max_position_value = portfolio_value * self.risk_config.max_position_size * 0.98  # Add 2% buffer
        max_position_size = max_position_value / current_price
        
        # For position closure, use the actual position size
        asset = "default"
        current_position = self.positions.get(asset, 0)
        
        if action < 0 and current_position > 0:  # Closing long position
            # Calculate closure size based on current position
            # action = -0.25 means close 25% of current position
            close_size = current_position * abs(action)
            trade_size = -close_size
            
            # For complete closure (action <= -1.0), close entire position
            if abs(action) >= 1.0:
                trade_size = -current_position
        else:  # Opening new position or adding to position
            # Calculate target position size based on action
            # action = 0.5 means target 50% of max_position_size
            target_size = max_position_size * action
            
            # Calculate required trade size
            trade_size = target_size - current_position
            
            # Ensure we don't exceed position limits
            new_position_value = (current_position + trade_size) * current_price
            if new_position_value > max_position_value:
                trade_size = (max_position_value / current_price - current_position)
        
        # Calculate trade details
        trade_details = self._calculate_trade_revenue(asset, trade_size, current_price)
        
        # Prepare trade result
        trade_result = {
            "timestamp": timestamp,
            "type": "buy" if trade_size > 0 else "sell",
            "price": current_price,
            "size": abs(trade_size),
            "position": sum(self.positions.values()),
            "balance": self.cash,
            "portfolio_value": self.get_portfolio_value({"default": current_price}),
            "entry_price": self.entry_prices.get(asset, current_price)  # Add entry price to result
        }
        
        # Update positions and entry prices
        if trade_size < 0 and current_position > 0:  # Position closure
            close_size = min(abs(trade_size), current_position)
            new_position = current_position - close_size
            
            if abs(new_position) < 1e-8:  # Complete closure
                del self.positions[asset]
                del self.entry_prices[asset]
            else:  # Partial closure
                self.positions[asset] = new_position
        elif trade_size > 0:  # Opening/increasing long position
            new_position = current_position + trade_size
            self.positions[asset] = new_position
            
            # Calculate weighted average entry price using actual trade size
            if asset in self.entry_prices:
                # Update existing position's entry price
                old_value = current_position * self.entry_prices[asset]
                new_value = trade_size * current_price
                total_size = current_position + trade_size
                self.entry_prices[asset] = (old_value + new_value) / total_size
            else:
                # For new positions, use current price
                self.entry_prices[asset] = current_price
        
        # Update cash balance
        if "cost" in trade_details:
            self.cash -= trade_details["cost"]
        if "revenue" in trade_details:
            self.cash += trade_details["revenue"]
        
        # Add revenue/cost and PnL
        trade_result.update({k: v for k, v in trade_details.items() 
                           if k in ["revenue", "cost", "pnl"]})
        
        # Record trade
        self.trades.append(trade_result)
        
        return trade_result
```

```
            print(f"Trade sizes: {self.trade_sizes[asset]}")
            
            # Calculate weighted average entry price
            total_size = sum(size for size in self.trade_sizes[asset].values())
            weighted_sum = sum(price * size for price, size in self.trade_sizes[asset].items())
            self.entry_prices[asset] = weighted_sum / total_size
            
            print(f"Total size: {total_size}")
            print(f"Weighted sum: {weighted_sum}")
            print(f"New entry price: {self.entry_prices[asset]}")
        
        # Update cash balance
        if "cost" in trade_details:
            self.cash -= trade_details["cost"]
        if "revenue" in trade_details:
            self.cash += trade_details["revenue"]
        
        # Add revenue/cost and PnL
        trade_result.update({k: v for k, v in trade_details.items() 
                           if k in ["revenue", "cost", "pnl"]})
        
        # Update position in result after all changes
        trade_result["position"] = self.positions.get(asset, 0)
        
        # Record trade
        self.trades.append(trade_result)
        
        return trade_result
```

아주 간단히 요약하면,

	•	experimental_backtester.py(혹은 ExperimentalBacktester)는 “향상된(실험적) 백테스터”

두 가지가 중복되면서 “어떤 부분은 단순 로직, 어떤 부분은 정교한 로직”이 서로 겹쳐 있습니다. “실제 프로젝트에서 하나로 통합해야 하나?” 라고 물어보면, 보통은 다음과 같은 방식으로 정리합니다:

1) ExperimentalBacktester가 기존 BacktestEngine의 ‘상속 + 오버라이딩’을 통해 확장 버전인 경우

만약 experimental_backtester.py 내의 ExperimentalBacktester가, BacktestEngine을 상속받아서 “향상된 기능”을 넣은 버전이라면(즉, class ExperimentalBacktester(BacktestEngine): ...), 원래 backtest.py나 BacktestManager.py에서 쓰이던 단순 로직과 충돌하는 부분이 생깁니다.
	•	예: BacktestManager.run_backtest() 안에서

backtester = BacktestEngine(...)  # 예전 코드

대신

backtester = ExperimentalBacktester(...)  # 새 코드

로 바꾸면, “부분 청산·평단가·다중 자산” 등을 지원하는 “확장된 로직”이 적용될 것입니다.

이 경우 **“통합”**이란,
	•	(A) 기존 BacktestManager에서 ExperimentalBacktester를 대신 사용하도록 변경
	•	(B) “옛날 단순 backtest”가 불필요하면 제거 or deprecated
	•	(C) 혹은 “classic” / “experimental” 모드를 설정해서, 선택적으로 어느 백테스터를 쓸지 결정

2) 실제 프로젝트에서 “둘 다” 쓰고 싶은 경우

혹은 “실험적 로직”이 아직 완전히 안정화되지 않아, 기존 로직(backtest.py / BacktestManager)을 그대로 유지하면서, 원하는 상황에서만 ExperimentalBacktester를 쓰는 경우도 많습니다.
	•	예: backtest_manager.py 안에

def run_backtest(self, data: pd.DataFrame, use_experimental=False):
    if not use_experimental:
        backtester = BacktestEngine(...)  # 옛날 로직
    else:
        backtester = ExperimentalBacktester(...)  # 새 로직
    
    return backtester.run(...)

처럼 분기하게 만들 수도 있죠.

3) 실무에서 “통합”은 보통 이렇게 한다
	1.	기존 BacktestEngine(단순)와 ExperimentalBacktester(확장)를 비교
	2.	“Experimental에서만 필요한 로직” (예: 다중 자산, 부분청산, 평단 추적)을 옵션 처리하거나, 별도 메서드로 만들어서
	3.	BacktestEngine 쪽을 “기능적으로” 확장 → 최종적으로 “Experimental”에서 쓰던 핵심 로직을 통합
	4.	그러면 기존 “backtest_manager.py”가 “새로운 BacktestEngine(=ExperimentalBacktester)를 완전히 대체”할 수 있음
	5.	이후 “옛날 코드는 deprecated or 삭제”

즉, 지금 experimental_backtester.py가 “정말 메인 로직으로 자리 잡을 만한 안정성인지”, 그리고 “기존 simple BacktestEngine의 호환성을 끊어도 되는지”를 판단한 뒤, 최종적으로 하나로 합치는 식이 실무에선 흔합니다.

4) “통합해야 되나?” 라는 질문에 대한 Tip
	•	만약 기존 backtest.py(단순 로직, 간단 기능)도 “빠르게 샘플 테스트하려는 용도”로 계속 쓰이고,

	1.	호출 시그니처:
