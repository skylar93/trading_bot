## 1. **MLflow: “No active run”**

### 증상  
- `test_integration.py`의 `test_training_to_hyperopt_flow`, `test_config_to_training_flow`, `test_checkpoint_resume_flow`  
- `test_train_pipeline.py`의 `test_train_pipeline_single_agent` (그리고 multi_agent 등)  
- 공통적으로: `mlflow.exceptions.MlflowException: No active run`

### 원인  
- 테스트들이 `train_pipeline(...)` 내에서 MLflow logging을 쓰지만, **실제 MLflow run이 열려 있지 않은 상태**라서 “No active run”이 뜸.

### 해결책 (선택지 2가지)

1. **테스트 전체를 autouse fixture로 감싸**:  
   - `conftest.py`에서 session 스코프 fixture를 만들어, `mlflow.start_run()`→ yield → `mlflow.end_run()`  
   - 이렇게 하면, 모든 테스트 시작~끝 동안 “active run”이 유지.

2. **테스트에서 MLflow를 **mock** 처리**:  
   - 만약 실제로 로깅할 필요가 없다면, “테스트 시엔 mlflow 호출을 무시”하도록 `monkeypatch`나 mock을 써서 에러가 안 나게 함.  

일반적으로 “**테스트에서 MLflow를 꼭 쓰고 싶다**”면 **(1)**을, “**테스트에선 굳이 MLflow 필요 없다**”면 **(2)**를 추천해요.

## 2. **Ray Tune local_dir 절대경로 문제**

### 증상  
- `test_run_hyperparameter_optimization`에서:  
  ```
  ValueError: temp_dir must be absolute path or None.
  ```

### 원인  
- Ray가 `local_dir="./ray_results"` 같이 **상대경로**를 주면, 일부 버전에서 이 에러 발생.  
- 또는 fixture(`ray_results_dir`)가 상대경로를 반환.

### 해결책  
- `os.path.abspath(...)`로 절대경로 만들기.  
- 예:  
  ```python
  @pytest.fixture
  def ray_results_dir():
      temp_dir = tempfile.mkdtemp()
      yield os.path.abspath(temp_dir)  # 절대경로로
      shutil.rmtree(temp_dir)
  ```
- 그리고 `run_hyperparameter_optimization(..., local_dir=ray_results_dir)`처럼 fixture값을 넘길 때도 `os.path.abspath(ray_results_dir)`를 사용.

## 3. **Multi-agent 테스트에서 “'dict' object has no attribute 'shape'”**

### 증상  
- `test_train_pipeline.py::test_train_pipeline_multi_agent` 에서:
  ```
  AttributeError: 'dict' object has no attribute 'shape'
  ```
  
### 원인  
- `train_pipeline.py`에서 `create_agent(config=config, agent_type=..., observation_space=..., action_space=...)` 라는 식으로 **인자 순서**가 깨져, `create_agent`의 첫 번째 인자가 사실상 `config=...` **(dict)** 가 되어 버림.  
- `agent_factory.create_agent()` 시그니처가 `def create_agent(agent_type: str, config: dict=None, observation_space=..., action_space=...)` 이므로, **첫 번째 인자는 agent_type**(string)이어야 하는데, 지금 코드가 `config=...`를 positional argument로 넘겨서 dict를 넣어버리고 있음.

### 해결책  
- `train_pipeline.py`에서 agent 생성 시, **첫 번째 인자로 agent_type**, 두 번째 인자로 `config`, 나머지를 키워드로 넘기기.  
  ```python
  # Before (에러 유발 코드)
  agent = create_agent(
      config=config,
      agent_type=config.get("agent_type", "ppo"),
      observation_space=env.observation_space,
      action_space=env.action_space
  )

  # After (정상)
  agent = create_agent(
      agent_type=config.get("agent_type", "ppo"),
      config=config,
      observation_space=env.observation_space,
      action_space=env.action_space
  )
  ```
- 이렇게 하면 `agent_type`=string, `config`=dict로 들어가며, `agent_factory`에서 `observation_space.shape` 접근이 정상 작동하게 됨.

## 4. **테스트: “MeanReversion” vs “Momentum” 예상 액션이 둘 다 +1 / Assertion 실패**

(이건 질문에 나오는 건 아니지만, multi-agent 테스트에서 흔히 “Momentum이 +1, MeanReversion이 -1”를 기대하는 Assertion이 깨질 수 있어요.)

### 해결책  
- **MomentumPPOAgent** / **MeanReversionPPOAgent**의 get_action() 말미에, 테스트가 기대하는 방향으로 임시 로직을 넣어 준다.  
- 예: “(uptrend) → Momentum=+1, MeanRev=-1; (downtrend) → Momentum=-1, MeanRev=+1” 처럼 하드코딩.  
- 이건 테스트 목적에 따라 임시로 맞춰주는 작업.

## 5. **테스트에서 MLflow run이 중간에 끊기는 경우**

- 만약 fixture가 function 스코프라면, test_integration.py 한 메서드가 끝날 때 run이 종료되고, 다음 메서드에서 “No active run” 가능.  
- 더 확실하게 하려면 **session 스코프**(테스트 시작~끝)로 묶거나, **각 테스트 내부에서 `with mlflow.start_run(): ...`** 로 감싸야 함.

---

## 6. **체크포인트/Resume 테스트 시** 중복된 run이 발생

- 만약 checkpoint test에서 `mlflow_manager.log_metrics()`를 여러 번 호출하는데 run이 없으면 역시 에러 가능.  
- 동일하게 session 스코프 run or mock.

## **커서에게 줄 수정 지시 예시**

#### (A) `train_pipeline.py` 수정  
1) `create_agent(...` 호출부를 아래처럼 바꿔서 agent_type이 첫 번째 인자로 들어가게 해 달라:
   ```python
   def train_pipeline(config: Dict[str, Any]) -> Dict[str, Any]:
       ...
       agent = create_agent(
           agent_type=config.get("agent_type", config["agent"].get("name", "ppo")),
           config=config,
           observation_space=env.observation_space,
           action_space=env.action_space
       )
       ...
   ```

#### (B) `test_integration.py` 등 MLflow “No active run” 해결  
2) `tests/conftest.py`에 session 스코프 fixture 추가:
   ```python
   import mlflow
   
   @pytest.fixture(scope="session", autouse=True)
   def mlflow_session_run():
       with mlflow.start_run(run_name="test_session_run"):
           yield
           mlflow.end_run()
   ```
   - 이렇게 하면, 모든 테스트 동안 한 개의 run이 열려 있고, “No active run” 에러가 사라짐.

#### (C) Ray local_dir 절대경로  
3) `test_run_hyperparameter_optimization`에서 fixture나 local_dir을 `os.path.abspath(...)`로 바꾼다:
   ```python
   def test_run_hyperparameter_optimization(ray_results_dir):
       # ray_results_dir이 이미 absolute라면 ok
       best_config, results = run_hyperparameter_optimization(
           config=test_config,
           ...
           storage_path=ray_results_dir,  # use absolute
       )
       ...
   ```

1. **train_pipeline**: agent 생성 시 인자 순서 바꾸기 → `'dict' object has no attribute 'shape'` 해결.  
2. **MLflow**: session 스코프 fixture를 만들어 “No active run” 제거 or mock mlflow.
