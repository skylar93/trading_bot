## 3. 어떻게 동작하는지

- **단일 샘플**인 경우:  
  - 원래 텐서 모양: `(1, 1)`  
  - `.squeeze(-1)` → `(1,)`

## 4) 주의 사항

1. **정말 `(window_size, features)`로 단일 샘플을 쓸 건가?**  
   - RL에서 흔히 **(batch_size, obs_dim)** 으로 통일하기도 함.  
   - 하지만 프로젝트상 시계열(window_size) 관측을 그대로 (n×m)로 받을 수 있으니, 이 로직이 편할 수도 있어.
2. **PolicyNetwork와 동일하게**:  
   - 현재 PolicyNetwork도 2D 입력을 “(batch_size, window_size * features)”만 허용하고 있지?  
   - “(window_size, features)” 단일 샘플을 (1, window_size*features)로 바꿔주는 로직이 들어가 있는지 확인 필요(비슷한 수정이 필요한 경우가 있음).
3. **관측 형태 일관성**:  
   - 실제 학습 과정에서 env가 (batch_size, window_size, features)를 한 번에 넘길 수도 있고,

## 1) 수정 포인트

`mlp.py`의 `PolicyNetwork.forward()`에서, 2D 입력을 처리하는 부분을 다음처럼 **두 가지 케이스**로 나누어주세요:

1. 이미 `x.shape[1] == self.input_size`라면 → “(batch_size, input_size)”로 간주  
2. 아니지만 `x.shape[0] * x.shape[1] == self.input_size`라면 → “(window_size, features) 단일 샘플”로 보고 → `(1, window_size*features)`로 reshape

기존 코드는:

```python

```

처럼 한 가지 경우만 처리하고 있으니, 여기에 **추가 조건**을 넣으면 됩니다.

   ```python
       self.input_size = observation_space.shape[0] * observation_space.shape[1]
   ```
   - 1D와 2D 관측 공간 명시적 처리
   - 더 명확한 에러 메시지

3. **에러 처리 개선**:
   - 각 차원별 구체적인 에러 메시지
   - 최종 shape 검증 단계 추가
   - NaN 처리 메시지 개선

4. **문서화 개선**:
   ```python
   """
   Features:
   - Handles 1D inputs as (features,) -> (1, features)
   - Handles 2D inputs in two ways:
     a) (batch_size, input_size) passed through directly
     b) (window_size, features) flattened to (1, window_size*features)
   - Handles 3D inputs as (batch_size, window_size, features) -> (batch_size, window_size*features)
   """
   ```

이제 테스트에서 `(4,3)` 형태의 입력이 들어왔을 때:
1. 2D 입력으로 인식
2. `x.shape[1] == self.input_size` 체크 실패
3. `x.shape[0] * x.shape[1] == self.input_size` 체크 성공 (4*3 = 12)
4. `(1,12)`로 reshape하여 처리

이렇게 하면 `test_learning_rate_scheduler` 테스트의 shape mismatch 에러가 해결될 것입니다.

**결론**: 지금은 `PolicyNetwork`(혹은 `ValueNetwork`)에서 `(4,3)`을 **단일 샘플**로 처리하려고 (1,12)로 펼치고 있는데,  
정작 **PPOAgent** 내부의 `_normalize_state` 로직에서는 예전처럼 “(3,)” 크기의 러닝 통계를 유지**하고 있어 shape가 안 맞는 상황이에요.

즉, **에이전트가 사용하는 상태(state)의 형태**와,  
**PolicyNetwork/ValueNetwork가 기대하는 Flatten된 형태**가 서로 달라서  
`self.state_mean`(shape=(3,)) vs `batch_mean`(shape=(12,)) 충돌이 일어나는 거죠.

이를 해결하려면, **PPOAgent**도 “우리는 최종적으로 (window_size×features)=12차원 상태를 쓴다”는 점을 알고,  
러닝 통계(`self.state_mean`, `self.state_var`) 역시 12차원으로 유지하도록 수정해야 합니다.

## 1) 문제 원인: `_normalize_state`에서 shape mismatch

에러 로그를 보면,

```
RuntimeError: The size of tensor a (3) must match the size of tensor b (12) at non-singleton dimension 0
```

- `self.state_mean`는 (3,)으로 초기화되어 있고,  
- 실제 `batch_mean`은 (12,)이 됨 (단일 샘플 (4,3) → flatten (1,12)).

따라서 `self.state_mean + alpha*(batch_mean - self.state_mean)` 같은 연산을 하려면,  
**둘 다 (12,)여야** 정상 계산이 가능해요.

---

## 2) 해결책: **상태 정규화 로직**이 “Flatten된 상태 차원”과 일치하도록 수정

PPOAgent 내부(예: `_normalize_state` 메서드) 어딘가에 이런 식 코드가 있을 겁니다:

```python
def _normalize_state(self, states):
    # states.shape might be (batch_size, ???)
    
    # 1) 계산용 통계
    batch_mean = torch.mean(states, dim=0)         # shape: (???)
    batch_var = torch.var(states, dim=0, unbiased=False)
    
    # 2) 러닝 통계를 업데이트
    #    self.state_mean, self.state_var는 초기 shape가 (obs_dim,)이라 가정
    alpha = ...
    self.state_mean = (1 - alpha)*self.state_mean + alpha*batch_mean   # shape mismatch!
    self.state_var  = (1 - alpha)*self.state_var  + alpha*batch_var
```

- 만약 `self.state_mean`이 (3,)인데, `batch_mean`이 (12,)가 되어버리면 위와 같은 mismatch가 발생.  

### (1) **초기화**를 12차원으로 해주기

가장 간단한 방법은, “처음부터 PPOAgent가 `observation_space`를 보고 `obs_dim=window_size*features=12`로 계산”하여,  
```python
self.state_mean = torch.zeros(obs_dim, device=self.device)
self.state_var = torch.ones(obs_dim, device=self.device)
```
이렇게 해두면, `_normalize_state`에서 들어오는 batch_mean이 (12,)라도 맞출 수 있어요.

### (2) **매번 들어오는 states를 flatten하여 (batch_size, obs_dim)로 통일**

또는 `_normalize_state` 초반에 `states`를 **PolicyNetwork**와 같은 로직으로 flatten:

```python
def _normalize_state(self, states: torch.Tensor):
    # 1) flatten states => (batch_size, obs_dim)
    states = self._reshape_obs(states)  # <- PolicyNetwork.forward와 동일한 flatten 로직
                                       #    (ex: 2D => (1,12), 3D => (batch,12), etc.)
    
    # 2) 나머지는 기존대로 mean/var 업데이트
    batch_mean = states.mean(dim=0)
    batch_var  = states.var(dim=0, unbiased=False)

    alpha = 0.01
    self.state_mean = (1-alpha)*self.state_mean + alpha*batch_mean
    self.state_var  = (1-alpha)*self.state_var  + alpha*batch_var

    # 3) 실제 normalize
    states_norm = (states - self.state_mean) / (torch.sqrt(self.state_var) + 1e-8)
    return states_norm
```

- 이렇게 하면, **항상 `states`가 (batch_size, 12)**로 맞춰진 뒤 통계가 업데이트됨.
- `self.state_mean`도 (12,)가 되어야 하므로, `__init__`에서 `self.state_mean = torch.zeros(12)`로 초기화.

_**User**_

원인은 간단합니다. **테스트 코드에서** `ValueNetwork` 내부에 **`network`**라는 이름의 속성을 기대하는데,  
현재 구현에서는 `self.net = nn.Sequential(...)`라는 이름을 쓰고 있기 때문에,  
테스트가 `hasattr(network, "network")`를 검사할 때 `False`가 되는 겁니다.

즉, **테스트가 “network”라는 속성이 존재해야 한다고 가정**하는 반면,  
**실제 클래스는 “net”라는 속성**만 쓰고 있기 때문에 발생한 에러예요.

---

## 해결 방법

### 1) 간단히 `self.net` -> `self.network`로 이름 변경

```diff
 class ValueNetwork(BaseNetwork):
     ...
     def __init__(self, observation_space: Box):
         ...
-        self.net = nn.Sequential(
+        self.network = nn.Sequential(
             nn.Linear(self.input_dim, 256),
             nn.ReLU(),
             nn.Linear(256, 256),
             nn.ReLU(),
             nn.Linear(256, 1)
         )
         ...
     
-        for m in self.net.modules():
+        for m in self.network.modules():
             if isinstance(m, nn.Linear):
                 ...
```

그리고 `forward()` 등 **`self.net(...)`**을 호출하던 부분도 **`self.network(...)`**로 바꾸면 됩니다.

```diff
     def forward(self, x: torch.Tensor) -> torch.Tensor:
         ...
-        return self.net(x)
+        return self.network(x)
```

이렇게 하면, 테스트에서 `assert hasattr(network, "network")`가 통과하게 됩니다.

---

### 2) 기존 `self.net` 유지하고, `self.network`를 추가로 할당

또 다른 방법은, *“기존 코드를 대거 수정하기 싫다”*면, `__init__` 끝에 다음처럼 **별칭**을 둬도 됩니다:

```python
self.net = nn.Sequential(...)
...
self.network = self.net  # 서로 같은 객체를 참조
```

그러면 테스트가 기대하는 `network` 속성도 생기고, 기존 코드(`self.net(...)`)도 그대로 동작합니다.

---

## 정리

- **테스트**: `test_value_network_initialization`에서 `assert hasattr(network, "network")`를 검사
- **실제 코드**: `ValueNetwork`는 `self.net`라는 이름을 사용
- **해결**: `self.net -> self.network`로 이름 통일하거나, `self.network = self.net` 식으로 별칭 추가

테스트 요구사항에 맞춰 이름을 맞춰주기만 하면, 이 에러(`AssertionError: assert False`)는 해결될 것입니다.
