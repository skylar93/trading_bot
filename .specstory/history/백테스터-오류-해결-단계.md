## 1. `No 'action' field in trade` 문제

### 현상

- 통합 테스트에서 `No 'action' field in trade: {...}` 라고 실패합니다.
- DummyAgent, PPOAgent 등을 써서 백테스트 돌렸는데, 최종적으로 만들어진 `trades` 리스트를 보면 `"action"` 항목이 없습니다.
- 실제 백테스터 로그를 보면 `{'timestamp': ..., 'symbol': 'default', 'price': ..., 'amount': ..., 'type': 'buy', 'fee': ..., 'success': True, ...}` 식으로는 있는데 `action` 키가 누락되어 있습니다.

### 원인

1. **백테스터(BaseBacktester/RiskAwareBacktester)** 구현부에서, 에이전트가 만든 action(예: +0.5, -0.5 등)을 “type: buy/sell”로만 변환하고, 정작 `trade["action"]` 필드는 저장하지 않는 것.
2. 결과적으로 `trades`에 `"action"`이 들어가지 않으니, 테스트가 `assert "action" in trade`를 못 통과.

### 해결방법

- **백테스터에서 trade를 생성할 때 `trade["action"] = agent_action`을 명시적으로 추가**하면 됩니다.

#### 예시 수정

```python
# pseudo-code: base_backtester.py or RiskAwareBacktester inside _execute_trade or similar
def _execute_trade(self, agent_action: float, current_price: float):
    trade = {}
    # 기존 필드들
    trade["timestamp"] = current_time
    trade["symbol"] = self.symbol
    trade["price"] = current_price
    trade["amount"] = size  # ex) abs(agent_action) * ...
    trade["type"] = "buy" if agent_action >= 0 else "sell"
    trade["fee"] = ...
    trade["success"] = True

    # 추가: action 필드 직접 저장
    trade["action"] = agent_action  

    self.trades.append(trade)
```

- 위처럼 백테스터 측에서 `action`을 저장해 주면, 테스트에서 요구하는 구조를 만족하게 됩니다.

## 2. `(slice(None, None, None), 3)` 또는 `(Ellipsis, 3)` 에러

### 현상

- 백테스터가 전략에게 `strategy.get_action(state)`를 호출했을 때, 에이전트가 **정상적인 float/ndarray** 대신 “`(slice(None, None, None), 3)`”나 “`(Ellipsis, 3)`” 등을 반환하게 됩니다.
- 그 결과 백테스터가 “Error getting action from strategy: (slice(None, None, None), 3)” 라는 에러 로그를 반복적으로 남김.

### 대표 원인

1. **MeanReversionPPOAgent**, **MomentumPPOAgent**에서 **flatten된 state**에 대해서 “close_prices”를 추출하려고 `[3::5]` 같은 슬라이싱을 시도함.
2. 하지만 **시나리오별 추가 feature**가 붙어서, 배열 길이가 5의 배수가 깨지거나, 실제 shape이 달라짐.
3. NumPy가 “`[3::5]`” 연산을 해석하려다 “`(slice(None, None, None), 3)`” 식의 예기치 않은 **슬라이스 객체**가 반환 → 최종 액션이 슬라이스 형태로 튀어나옴.

### 해결 아이디어

- **flatten된 state**에서 OHLCV를 가져오기 전에, 다음 절차를 거쳐야 함:

1. **원본의 (window_size, 5) 길이**를 파악 (예: 20 * 5 = 100).
2. **추가 feature**(3개 등)가 붙었다면, 최종 길이는 103이 됨.
3. **state[:, :100]** 부분만 잘라서 `(batch, 100)` → `(batch, window_size, 5)` 로 reshape
4. 그 뒤 `close = reshaped[..., 3]`

예시 (MeanReversionPPOAgent) 내 `get_action`에서 “trend_strength” 계산할 때:

```python
def get_action(self, state: np.ndarray, deterministic: bool = False) -> np.ndarray:
    ...
    # -- (앞부분) state flatten + reversion_features concat까지 한 뒤, state.shape ~ (batch, original_len + 3)
    batch_size = state.shape[0]
    original_len = self.original_obs_space.shape[0] * self.original_obs_space.shape[1]  # 20*5=100
    # OHLC part only
    ohlc_part = state[:, :original_len]
    ohlc_part = ohlc_part.reshape(batch_size, self.original_obs_space.shape[0], self.original_obs_space.shape[1])
    close_prices = ohlc_part[..., 3]

    # trend_strength = (close_prices[:, -1] - close_prices[:, 0]) / close_prices[:, 0]
    # ... etc ...
```

- MomentumPPOAgent도 동일하게 고쳐야 합니다.

     ```

4. NaN 데이터 대응:
   - 만약 NaN 들어오면, agent가 np.diff(prices) 등에서 에러를 낼 수 있으니, 백테스터 쪽에서 ffill/bfill 해주거나, 에이전트 내부에서 NaN을 0으로 처리하는 로직을 추가.

일반적으로 **백테스터 쪽에서 `trade["action"] = agent_action`을 추가**하는 것은, 새로운 오류를 만들 가능성이 비교적 낮은 편입니다. 보통은 테스터가 `agent_action`을 잘 받고 있어야 하며, 그 값(예: `+0.5`나 `-0.3`)을 그대로 기록만 하면 되기 때문이죠.  

다만, 다음 사항들을 확인해 두면 “새로운 에러가 날 것 같은” 걱정을 줄일 수 있습니다:

## 1. `agent_action` 값이 어디서 오는가?
- 백테스터가 `strategy.get_action(state)`로부터 받은 결과를 **바로** `agent_action`으로 사용하면 됩니다.  
- 예를 들어 `agent_action = strategy.get_action(...)`이 float(혹은 크기가 1인 ndarray) 형태로 잘 반환된다면, 그대로 `trade["action"] = agent_action`을 넣으면 됩니다.  

백테스터 코드에서 흔히 이런 식일 것입니다:

```python
agent_action = self.strategy.get_action(current_state)
# position sizing / risk check ...
# execute trade
trade = {
    "timestamp": current_time,
    "symbol": self.symbol,
    "price": current_price,
    "amount": trade_size,
    "type": "buy" if agent_action >= 0 else "sell",
    "fee": calculated_fee,
    "success": True
}
# 추가
trade["action"] = agent_action

self.trades.append(trade)
```

만약 `agent_action`이 전혀 준비되지 않은 변수라면, 그 부분을 먼저 맞춰야 합니다(예: `agent_action`을 local scope에서 계산해야 하거나, 파라미터로 넘겨받아야 함).

## 2. 만약 `action`을 추가해서 에러가 난다면?
“새로운 에러”라고 한다면 크게 두 가지 경우를 생각할 수 있습니다:

1. **데이터 타입 문제**  
   - 예: `agent_action`이 ndarray(크기 1짜리)인데, `float(agent_action)` 변환 없이 바로 dict에 넣었더니 JSON 변환 시 문제가 생긴다거나.  
   - 해결 방법: `float(agent_action)` 또는 `agent_action.item()` 등을 써서 **확실히 숫자(float) 스칼라**로 저장해 주면 됩니다.

2. **trade 생성 시점이 다른 곳에서 사용되는 경우**  
   - 예: 어떤 모듈에서 `trade` 구조체를 그대로 참조한다든지, “기존에 `action` 필드가 없을 것이라 가정”했던 로직이 있다든지.
   - 해결 방법: 그 부분에서 `action` 필드가 생겨도 문제가 없도록 하거나, 굳이 쓰지 않는다면 무시해도 됩니다.

대부분은 1번에 가까운 문제라서, “`action`을 ndarray나 tuple처럼 넣어놨더니 JSON export 시 에러” 같은 식으로 발생할 수 있습니다. 이런 경우, 테스트 코드가 “`assert isinstance(trade["action"], (int, float, np.ndarray))`” 식으로 검사한다면, ndarray라도 괜찮지만, 혹시 최종 DB 저장이나 CSV export 시 문제될 여지가 있으니, 보통은 **float(단일 값)** 형태로 저장하는 걸 권장합니다.

---

## 3. 다른 부분에서 `action` 필드를 해석하지 않는가?
- 예를 들어 “trade action이 +0.5면 amount를 얼마로 계산해야 하나?” 같은 로직이 이미 백테스터 내에 있다면, action을 중복으로 처리하지 않도록 주의해야 합니다.
- 하지만 단순히 “테스트에서 action 필드를 요구하니, 기록만 해 두겠다” 수준이라면, **추가 필드를 달아두는 정도로는 큰 충돌이 생길 가능성이 낮습니다.**

---

## 4. 정리
- **“action 필드를 넣으면 새로운 에러가 날 것”** → 보통은 그렇지 않고, 오히려 테스트가 원하는 구조(`"action" in trade`)를 충족하므로 문제를 해결해 줍니다.  
- 혹시나 타입이나 JSON export 등에서 에러가 생길 수 있다면, `action`을 float로 강제 변환(`trade["action"] = float(agent_action)`)하는 정도로 쉽게 해결할 수 있습니다.
- 추가로 MeanReversionPPOAgent, MomentumPPOAgent가 `(slice(None, None, None), 3)` 같은 결과를 리턴하는 이슈는 **에이전트 내부의 `close_prices` 슬라이싱 로직**을 고쳐야 하므로, **별도의 작업**입니다. “action 필드를 추가하는 것” 자체와는 직접적인 충돌이 거의 없으니 안심하고 1번 문제부터 해결해 두셔도 됩니다.

## 원인 정리

1. **에이전트(`get_action`)가 실제로 dict를 반환**:  
   예를 들어, “MeanReversionPPOAgent”가 “{‘action_value’: 0.5, ‘some_extra_info’: ...}” 형태를 반환할 수도 있습니다. 혹은 “predict()”에서 뭔가 dict를 만들어 리턴하는 경우도 마찬가지입니다.

2. **혹은 백테스터가 잘못된 자료를 “action”에 저장**:  
   에이전트는 float을 반환하지만, 어딘가에서 “action”을 dict로 만들어 전달하고 있을 수도 있습니다. 예: “risk_check 결과”나 “trade_result”를 action에 할당해버린다거나.

3. **테스트/멀티에이전트 로직에서 “action”을 확장**:  
   다중 에이전트 구조에서 “{'id': agent_id, 'value': numeric_action, ...}” 형태를 리턴하는 식의 커스터마이징이 있을 수도 있습니다. 이 상태가 백테스터로 그대로 넘어가면 `action`이 dict가 되어버립니다.

## 해결책

핵심은 **“백테스터가 내부 로직에서 필요로 하는 action은 **반드시** float(혹은 단일 ndarray) 여야 한다.”** 라는 점입니다.

### 1) 에이전트가 반환하는 `action`을 float/ndarray로 제한

- **MeanReversionPPOAgent, MomentumPPOAgent, DummyAgent** 등이 `get_action()`에서 반드시 `float` 또는 `np.ndarray(shape=(1,))` 등을 반환하도록 수정해야 합니다.
- 예컨대 `return 0.5`나 `return np.array([0.5])` 식으로요.

### 3) 기존에 dict 형태를 반환하도록 만들어진 로직 제거

              * negative: sell (short)

                'symbol': asset,
                'price': current_price,
                'amount': 0,
                'fee': 0,

        if self.risk_manager:

## 5) “float object is not subscriptable” (Multi-agent)

멀티 에이전트 테스트에서 자주 나오는 에러: `TypeError: 'float' object is not subscriptable`

- 멀티 에이전트 로직 안에서 “`action[0]`” 혹은 “`action['some_key']`”를 하려는데, 지금은 각 agent가 float만 반환
- 예전에는 agent가 np.array([0.3]) 형태로 반환했고, 거기서 `[0]`를 취해 0.3을 얻었지만, 이제는 바로 0.3(float)로 반환하므로 subscript 불가

해결책:

- 멀티 에이전트가 여러 agent action을 합산(예: `(action1[0] + action2[0])/2`)하려면, **agent들도 공통 규격을 유지**해야 함
  - A) **모든 agent `get_action()`은 shape=(1,) ndarray**를 반환 → 그럼 multi-agent는 `action[i,0]` 식으로 접근 가능
  - B) **모든 agent `get_action()`은 float**를 반환 → 그럼 multi-agent는 `0.5*action1 + 0.5*action2` 식으로 쓰고, subscript를 없애야 함
- 어떤 방식을 택해도, **테스트와 멀티 에이전트 코드**를 맞춰야 함.

## 6) “NaN data triggered action error logs”

NaN 데이터가 들어간 상태로 agent가 “close_prices[-10]” 같은 인덱스를 접근하다 에러가 나서, 백테스터에서 “Error getting action”이 잔뜩 찍히는 상황입니다.

**대처 방안**:

- agent 내부에서 `prices = np.nan_to_num(prices, nan=last_valid)` 식으로 NaN을 제거
- NaN 비중이 너무 크면 action=0으로 처리, 혹은 early return
- test에서는 “NaN이 있어도 agent가 error 없이 0 action(또는 skip)한다”는 로직을 기대 → agent 코드를 그에 맞춰 방어적으로 짜거나, 백테스터가 NaN bar는 skip

## 정리 / 단계별 가이드

1. **Trade amount 양수화**: 이미 하셨듯이, `trade["amount"] = abs(...)`, `type = buy/sell`, `action = agent_action`로 저장  
2. **테스트 중 `assert something < 0` / `==0` 등과 충돌**: 
   - 테스트 코드를 열어, 예전 방식(음수 금액, 0번 거래)과 현재 방식(양수 금액, 실제 거래 발생)이 달라진 부분을 찾아 수정  
3. **MeanReversion/Momentum “(slice(None,...),3)” 에러**:  
   - `get_action()`에서 shape 분기 처리 (1D vs 2D vs 3D)  
   - NaN 방어 코드 (길이 체크, NaN 시 action=0 등)  
4. **멀티 에이전트 “float not subscriptable”**:  
   - 통일: agent action은 float → multi-agent 내에서 `action1 + action2` 등으로 합산, subscript 코드 제거  
   - (혹은 action은 shape=(1,) → multi-agent는 `action[0]` 사용)  
5. **Risk limit / drawdown**:  
   - RiskManager와 테스트가 동일한 drawdown 계산 로직 쓰는지 확인  
   - 예전처럼 “stop trades if drawdown>15%”가 동작 않으면, risk_manager.py나 test_scenario.py에서 계산 방식 불일치 확인
6. **NaN data**:  
   - agent가 NaN close price를 사용하기 전 방어 처리  
   - test도 “NaN이어도 error log 없어야 한다면” agent 또는 백테스터가 graceful하게 처리하도록 수정

        Calculate mean reversion specific features from the state.
        
        Args:
            state: Raw state observation
            
        Returns:
            Mean reversion features as numpy array
            
        Notes:
            - For 1D input: state[3] for close price
            - For 2D input: state[:, 3] for close prices
            - For 3D input: state[..., 3] for close prices
            - Returns zeros if insufficient data or too many NaNs
        """
        # Early return if state is invalid
        if not isinstance(state, np.ndarray):
            self.logger.warning(f"Invalid state type: {type(state)}, expected numpy array")
            return np.zeros(3, dtype=np.float32)
            
        # Handle different state shapes
        if state.ndim == 1:  # Single feature vector
            if len(state) < 4:
                self.logger.warning(f"State too short: {len(state)}, expected at least 4 features")
                return np.zeros(3, dtype=np.float32)
            close_prices = np.array([state[3]])  # Single close price
        elif state.ndim == 2:  # (window, features)
            if state.shape[1] < 4:
                self.logger.warning(f"Too few features: {state.shape[1]}, expected at least 4")
                return np.zeros(3, dtype=np.float32)
            close_prices = state[:, 3]  # Window of close prices
        elif state.ndim == 3:  # (batch, window, features)
            if state.shape[2] < 4:
                self.logger.warning(f"Too few features: {state.shape[2]}, expected at least 4")
                return np.zeros((state.shape[0], 3), dtype=np.float32)
            close_prices = state[..., 3]  # Batch of close price windows
        else:
            self.logger.warning(f"Invalid state dimensions: {state.ndim}, expected 1, 2, or 3")
            return np.zeros(3, dtype=np.float32)
            
        # Handle NaN values
        if np.isnan(close_prices).any():
            # If too many NaNs, return zeros
            if np.isnan(close_prices).mean() > 0.3:  # More than 30% NaNs
                self.logger.warning("Too many NaN values in close prices")
                shape = (close_prices.shape[0], 3) if close_prices.ndim > 1 else (3,)
                return np.zeros(shape, dtype=np.float32)
            # Otherwise, forward fill NaNs
            if close_prices.ndim == 1:
                close_prices = pd.Series(close_prices).fillna(method='ffill').fillna(method='bfill').values
            else:
                close_prices = pd.DataFrame(close_prices).fillna(method='ffill').fillna(method='bfill').values
        
        # Calculate features based on data shape
        if close_prices.ndim == 1:  # Single sample
            if len(close_prices) < self.rsi_window + 1:
                self.logger.warning(f"Insufficient data for RSI: {len(close_prices)} < {self.rsi_window + 1}")
                return np.zeros(3, dtype=np.float32)
                
            rsi = self._calculate_rsi(close_prices)
            bb_upper, bb_lower = self._calculate_bollinger_bands(close_prices)
            current_price = close_prices[-1]
            bb_upper_dist = (bb_upper - current_price) / current_price
            bb_lower_dist = (current_price - bb_lower) / current_price
            
            return np.array([rsi, bb_upper_dist, bb_lower_dist], dtype=np.float32)
            
        else:  # Batch processing
            batch_size = close_prices.shape[0]
            features = np.zeros((batch_size, 3), dtype=np.float32)
            
            for i in range(batch_size):
                prices = close_prices[i]
                if len(prices) < self.rsi_window + 1:
                    continue
                    
                rsi = self._calculate_rsi(prices)
                bb_upper, bb_lower = self._calculate_bollinger_bands(prices)
                current_price = prices[-1]
                
                features[i, 0] = rsi
                features[i, 1] = (bb_upper - current_price) / current_price
                features[i, 2] = (current_price - bb_lower) / current_price
                
            return features

    def get_action(self, state: np.ndarray, deterministic: bool = False) -> float:
        """
        Get action from policy network with mean reversion considerations.
        
        Args:
            state: Current state observation (1D, 2D, or 3D array)
            deterministic: Whether to use deterministic action selection
            
        Returns:
            float: Action value between -1 and 1
        """
        try:
            # Handle different state shapes for close price extraction
            if state.ndim == 1:  # Single feature vector
                close_prices = state[3:]
            elif state.ndim == 2:  # (window, features)
                close_prices = state[:, 3]
            elif state.ndim == 3:  # (batch, window, features)
                close_prices = state[..., 3]
            else:
                self.logger.warning(f"Invalid state dimensions: {state.ndim}")
                return 0.0
                
            # Simple NaN handling - just replace with zeros
            close_prices = np.nan_to_num(close_prices, 0.0)
            
            # Calculate RSI and Bollinger Bands
            rsi = self._calculate_rsi(close_prices)
            bb_upper, bb_lower = self._calculate_bollinger_bands(close_prices)
            current_price = close_prices[-1]
            
            # Calculate distances
            bb_upper_dist = (bb_upper - current_price) / current_price if current_price != 0 else 0.0
            bb_lower_dist = (current_price - bb_lower) / current_price if current_price != 0 else 0.0
            
            # Prepare state for network
            flat_state = state.reshape(1, -1)
            features = np.array([[rsi, bb_upper_dist, bb_lower_dist]])
            augmented_state = np.concatenate([flat_state, features], axis=1)
            
            # Get base action
            base_action = super().get_action(augmented_state.reshape(-1), deterministic)
            
            # Calculate trend strength (with basic shape handling)
            if len(close_prices) >= 10:
                trend_strength = (close_prices[-1] - close_prices[-10]) / close_prices[-10] if close_prices[-10] != 0 else 0.0
            else:
                trend_strength = 0.0
            
            # Simple mean reversion logic
            if rsi < self.oversold_threshold and bb_lower_dist > 0:
                action = base_action + 0.5  # Buy bias
            elif rsi > self.overbought_threshold and bb_upper_dist > 0:
                action = base_action - 0.5  # Sell bias
            else:
                action = base_action
            
            # Add trend bias
            action -= np.sign(trend_strength) * min(abs(trend_strength), 0.3)
            
            # Ensure action is float and clipped
            return float(np.clip(action, -1.0, 1.0))
            
        except Exception as e:
            self.logger.error(f"Error in get_action: {str(e)}")
            return 0.0
