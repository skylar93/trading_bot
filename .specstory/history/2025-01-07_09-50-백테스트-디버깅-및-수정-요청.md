## 1. 어떤 파일을 건드려야 할지 파악하는 방법

1. **실제 사용 중인 코드/테스트 파일 확인**  
   - 프로젝트 내에서 *실제 실행/적용 중인 백테스터*가 어느 것인지(예: CI/CD 스크립트나 main code path에서 불리는 백테스터)는 보통 한두 개뿐입니다.  
   - 만약 현재 `pytest`에서 문제가 발생하는 테스트가 **어떤 백테스터를 인스턴스화**해서 돌리고 있는지 확인해야 합니다.
     - 예: `test_backtest_execution.py`에서 `manager = BacktestManager(settings)` 이후 `run_backtest()` 하는데, 그 내부가 `RiskAwareBacktester`를 쓰고 있다면 → `risk_backtest.py` 안의 `RiskAwareBacktester`를 수정해야 함.
     - 반면 `test_experimental_backtester.py`에서 `backtester = ExperimentalBacktester(...)`를 직접 만들어 쓰고 있다면 → `experimental_backtester.py`를 수정해야 함.

2. **실제 에러 메시지가 어느 백테스터 클래스로부터 오는지**  
   - 예: `FAILED tests/test_backtest_execution.py::test_risk_management_integration`에서 “Position size 10.93% exceeds limit 10%”가 발생한다면, 그 에러가 `RiskAwareBacktester`의 로직(또는 `ExperimentalBacktester`)에서 나오는 것인지, 아니면 `backtest.py`의 `Backtester`를 통해 나오는 것인지 traceback이나 로그를 보면 힌트를 얻을 수 있습니다.

3. **테스트 파일 vs. 백테스터 클래스 맵핑**  
   - 예를 들어, 
     - `test_experimental_backtester.py` → `ExperimentalBacktester`
     - `test_backtest_execution.py` → `RiskAwareBacktester` (혹은 `Backtester` 계열)  
   - 이런 식으로 “어떤 테스트가 어떤 백테스터를 쓰고 있는지”를 파악하면, “어디를 고쳐야 하는지”가 좀 더 명확해집니다.

## 3. 일반적 케이스: **`test_backtest_execution.py`** → `RiskAwareBacktester` 쪽 수정

보통 “\_\_execution.py”나 “\_\_integration.py” 식 테스트 파일은 `RiskAwareBacktester`(=`risk_backtest.py`)를 통해 “실제 리스크 관리 + 포지션 크기 제한 + PnL 계산”을 검사하는 경우가 많습니다.  
- **`ExperimentalBacktester`**는 주로 `test_experimental_backtester.py`에서 검사할 가능성이 큽니다(파일 이름이 그런 식으로 짝지어져 있으니까요).  
- **`backtest.py`**(=`Backtester`)는 더 단순/레거시 방법이라면, 아마 `test_backtest.py` 같은 데서 쓸 수도 있습니다.

따라서, **`test_backtest_execution.py`에서 실패**하고 있다면, 대체로 **“리스크 관리”**(포지션 크기 초과 문제)와 **“PnL 계산”** 문제는 **`RiskAwareBacktester`**(=`risk_backtest.py`)를 수정해야 할 가능성이 큽니다.

만약 `test_backtest_execution.py` 내부를 열어 보면, 대개
```python

...

...
```
이런 식으로 되어 있을 텐데, 그 `manager.run_backtest()` 내부에서 **어느 백테스터 클래스를 인스턴스화**해서 쓰고 있는지 보시면 됩니다. 만약 `RiskAwareBacktester`라고 되어 있다면, 거기가 수정 대상인 거죠.
