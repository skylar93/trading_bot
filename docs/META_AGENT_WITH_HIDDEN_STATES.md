# 메타 에이전트의 서브 에이전트 내적 상태 활용 기능

## 개요

트레이딩 봇의 다중 에이전트 시스템에서 메타 에이전트(Meta-Agent)가 서브 에이전트(Sub-Agents)의 내적 상태(Hidden State/Latent Representation)를 활용하여 더 정교한 의사결정을 내릴 수 있도록 기능을 확장했습니다. 이 문서는 해당 기능의 구현 방식, 아키텍처 및 사용법을 설명합니다.

## 구현 아키텍처

### 1. 전체 흐름

현재 구현에서는 다음과 같은 흐름으로 서브 에이전트의 내적 상태가 메타 에이전트에 전달됩니다:

1. 서브 에이전트가 관측(observation)을 처리하며 히든 레이어 출력을 추출
2. 서브 에이전트의 `act_with_hidden_state()` 또는 `get_action_with_hidden_state()` 메서드가 액션과 함께 내적 상태를 반환
3. `MultiAgentManager`가 이 정보를 수집해 메타 에이전트에 제공
4. 메타 에이전트가 기존 관측에 내적 상태를 결합하여 더 풍부한 정보로 결정
5. 학습 과정에서도 경험(experience)에 내적 상태가 포함되어 메타 에이전트 학습에 활용

### 2. 주요 컴포넌트 변경사항

#### 서브 에이전트 (Sub-agents)
- `AssetSpecificAgent`, `CryptoAgent`, `EquityAgent` 등에 새로운 `act_with_hidden_state()` 및 `get_action_with_hidden_state()` 메서드 추가
- 기존 API와의 호환성 유지를 위해 원래 메서드(`act()`, `get_action()`)는 그대로 유지
- 신경망의 중간층에서 내적 상태(latent representation)를 추출하는 로직 추가

#### 메타 에이전트 (Meta-agent)
- `MetaNetwork` 클래스의 관측 처리 개선
- 어텐션 메커니즘으로 서브 에이전트의 내적 상태 통합 기능 추가
- 다양한 서브 에이전트의 히든 표현을 효과적으로 처리하는 아키텍처 도입
- Categorical 분포를 사용할 때 액션 값 범위 검증 및 보정 로직 추가

#### 다중 에이전트 관리자 (MultiAgentManager)
- 서브 에이전트로부터 액션뿐만 아니라 내적 상태도 수집하는 기능 추가
- `get_action_with_hidden_state()` 메서드 사용하여 내적 상태 수집
- 메타 에이전트 관측 구성 시 내적 상태 추가
- 메타 에이전트 경험(experience) 생성 시 내적 상태 포함
- 다양한 차원의 관측과 내적 상태를 일관되게 처리하기 위한 배열 평탄화 로직 추가
- `get_meta_observation` 및 `_create_meta_experience` 메서드에서 차원 불일치 문제 해결

#### 환경 (Environment)
- 서브 에이전트의 내적 상태를 처리할 수 있는 로직 추가
- 경험 수집 과정에서 내적 상태 정보 유지

## 사용법

### 1. 트레이닝 스크립트

새로 추가된 `training/train_meta_agent.py` 스크립트를 사용하여 내적 상태를 활용하는 메타 에이전트를 학습할 수 있습니다:

```bash
python training/train_meta_agent.py \
  --data_path data/crypto_daily.csv \
  --config_path configs/multi_agent_config.json \
  --episodes 200 \
  --window_size 60 \
  --use_hidden_states \
  --save_path models/meta_hidden
```

`--use_hidden_states` 플래그를 지정하면 서브 에이전트의 내적 상태를 메타 에이전트가 활용합니다.

### 2. 코드에서 직접 사용하기

코드에서 직접 내적 상태를 얻고 처리하는 방법은 다음과 같습니다:

```python
# 서브 에이전트에서 액션과 내적 상태 얻기
action, hidden_state = agent.get_action_with_hidden_state(observation)

# 기존 방식처럼 액션만 얻기
action = agent.get_action(observation)  # 내부적으로 get_action_with_hidden_state 호출하지만 히든 상태는 버림
```

## 메타 에이전트 관측 구조

메타 에이전트가 받는 최종 관측은 다음과 같은 구조로 구성됩니다:

```
[
  서브에이전트1_관측,
  서브에이전트2_관측,
  ...,
  서브에이전트N_관측,
  시장상태,
  서브에이전트1_내적상태,
  서브에이전트2_내적상태,
  ...,
  서브에이전트N_내적상태
]
```

## 중요 구현 세부사항

### 배열 차원 처리
서로 다른 형태와 차원의 관측 및 내적 상태를 효과적으로 처리하기 위해 다음과 같은 접근 방식을 채택했습니다:

1. **일관된 평탄화 로직**: 모든 관측과 내적 상태는 `flatten()` 메서드를 사용하여 1차원 배열로 변환 후 결합
2. **강력한 타입 검증**: 각 배열의 타입과 차원을 확인하고 필요시 변환하는 로직 추가
3. **자동 1차원화**: 다차원 배열을 자동으로 1차원으로 변환하여 일관된 처리 보장
4. **안전한 결합**: 차원 불일치 오류를 방지하기 위한 추가 검증 및 로깅

### 액션 분포 처리
Categorical 분포를 사용하는 경우 액션 값이 항상 유효한 범위(0 ~ n-1)에 있도록 `torch.clamp()` 함수를 사용하여 값을 보정합니다. 이는 특히 메타 에이전트가 이산적인 액션 공간을 사용할 때 중요합니다.

## 모델 아키텍처

내적 상태를 활용하기 위해 메타 에이전트 네트워크 아키텍처가 확장되었습니다:

1. **특성 추출기(Feature Extractor)**: 전체 결합 관측을 처리
2. **어텐션 메커니즘(선택적)**: 서브 에이전트의 내적 상태 간 관계 학습
3. **액터 네트워크**: 서브 에이전트 선택 또는 가중치 할당
4. **크리틱 네트워크**: 상태 가치 계산

## 하위 호환성

기존 코드와의 호환성을 유지하기 위해 다음과 같은 접근 방식을 채택했습니다:

1. 기존 API(`act()`, `get_action()`)는 그대로 유지하고, 새로운 함수(`act_with_hidden_state()`, `get_action_with_hidden_state()`)를 추가
2. 기존 API는 내부적으로 새 함수를 호출하고 액션만 반환하여 하위 호환성 보장
3. 새로운 기능을 사용하려면 확장된 API를 명시적으로 호출해야 함

이로 인해 기존 코드를 변경하지 않고도 필요한 곳에서만 새 기능을 활용할 수 있습니다.

## 문제 해결 및 디버깅

구현 과정에서 발생한 주요 문제와 해결책:

1. **차원 불일치 오류**: 서로 다른 형태의 관측과 내적 상태를 결합할 때 차원 불일치 문제가 발생했으나, 강화된 평탄화 로직으로 해결
2. **분포 범위 오류**: Categorical 분포에서 액션 값이 유효 범위를 벗어나는 문제가 발생했으나, 값 범위 검증 및 보정으로 해결
3. **다양한 네트워크 아키텍처 지원**: 서로 다른 구조의 서브 에이전트 네트워크에서 추출된 내적 상태를 통합하는 방법 개선

## 결론 및 이점

서브 에이전트의 내적 상태를 활용함으로써 메타 에이전트는 다음과 같은 이점을 얻을 수 있습니다:

1. **심층적 이해**: 단순 관측이나 액션보다 서브 에이전트의 의사결정 과정에 대한 더 깊은 이해
2. **상황 인식**: 서브 에이전트가 현재 상황을 어떻게 해석하는지에 대한 추가 정보
3. **보완적 전략**: 다양한 서브 에이전트의 강점을 더 효과적으로 활용
4. **효율적 학습**: 서브 에이전트의 지식을 내부 표현을 통해 더 효율적으로 활용

## 향후 개선 방향

1. **다양한 내적 상태 활용**: 여러 레이어의 내적 상태를 활용하거나 서브 에이전트의 특정 네트워크 부분에서 추출된 표현 활용
2. **동적 가중치 할당**: 시장 상황에 따라 서브 에이전트 내적 상태의 중요도를 동적으로 조정
3. **계층적 의사결정**: 다단계 의사결정 프로세스에서 내적 상태의 영향력 활용
4. **자기지도 학습(Self-Supervised Learning)**: 내적 상태를 예측하거나 이해하는 추가 학습 태스크를 통한 개선
5. **더 강력한 견고성**: 다양한 에이전트 구성과 관측 형태에 대한 자동 적응 기능 강화
